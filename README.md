# TestMu AI SDET-1 — Playwright + Gemini

## Overview

A local demo QA automation project using Playwright, TypeScript, REST API tests, and Google Gemini for AI-assisted failure explanation. This is a locally implemented demo application, not the TestMu production application.

## Requirements

- Node.js 20+ recommended
- npm
- A Google Gemini API key with access to the configured model and available quota for the real LLM integration test

## Setup

```powershell
npm install
npx playwright install chromium
Copy-Item .env.example .env
```

If `.env` already exists, do not overwrite it. Add your own key locally:

```dotenv
GEMINI_API_KEY=your_actual_key_here
GEMINI_MODEL=gemini-3.8-flash
```

Use a model ID enabled for your account. Model access and quota can vary. Never commit `.env` or share the key.

## Run checks

```powershell
npm run typecheck
npm test
```

Playwright starts the local demo app at `http://127.0.0.1:4173` while the tests run.

Run only the real Gemini integration test:

```powershell
npx playwright test tests/login/login.spec.ts --grep "failure explainer integration"
```

The integration test makes a real Gemini API call when `GEMINI_API_KEY` is set. It attaches the actual LLM response to the Playwright test and writes it to both:

- `test-results/ai-failure-explanation.md` (test-run output, ignored by Git)
- `artifacts/ai-failure-explanation.md` (reviewable assessment artifact; generated by running the integration test)

Do not commit an empty/template response. After a successful run, review `artifacts/ai-failure-explanation.md` and commit it with the code if it contains no secrets or sensitive page data.

## Implemented coverage

- Login: valid login, invalid credentials, required email validation, and neutral forgot-password confirmation
- Dashboard: widget data accuracy, filter states, logout, and mobile viewport overflow check
- REST API: valid/invalid/missing login payload, missing/invalid token, widget schema and data, known-user response, and unknown-user 404
- Gemini Failure Explainer: actual API call from Playwright, response attached to test results, and report saved locally/under `artifacts/`

## Known gaps — not passing tests

- Session expiry and brute-force lockout are not implemented in the demo
- Role/permission-based widget visibility is not implemented
- Full CRUD endpoints, rate limiting, deliberate 5xx simulation, and wider schema validation/error handling are not implemented
- The Failure Explainer currently analyzes controlled failure evidence in a dedicated test; it is not automatically invoked for every arbitrary failed test

These are documented gaps, not claims of completed functionality.

## Assessment artifacts

- `prompts.md` — actual Gemini Failure Explainer instructions and clearly labelled prepared test-generation prompts
- `test-cases/generated-test-cases.md` — module test catalogue, status, and required 3–5-line notes about initial issues and changes
- `ai-usage-log.md` — AI tools, outputs, and verification notes
- `artifacts/ai-failure-explanation.md` — actual Gemini response generated after a successful integration test
- `utils/failure-explainer.ts` — real Gemini API integration
